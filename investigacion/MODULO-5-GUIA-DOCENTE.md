# Módulo 5 — HTML con sentido: estructura, video y accesibilidad

## Decisión de secuencia

Se propone una última clase centrada en HTML antes de comenzar CSS como tema principal. Insertar un video por sí solo no justifica una clase de 90 minutos: se integra con la organización semántica de la página y decisiones básicas de accesibilidad. El módulo funciona como cierre y puente. CSS se reserva para el módulo 6, donde podrá diferenciarse con claridad estructura de presentación.

## Propósitos

- Diferenciar la función de HTML de la futura función de CSS.
- Comprender la idea de semántica mediante un mapa visual de `header`, `nav`, `main`, `section` y `footer`.
- Diferenciar un archivo reproducido con `video` de un recurso externo insertado mediante `iframe`.
- Usar una URL de inserción de YouTube, identificar el reproductor y evitar `autoplay`.
- Ofrecer un resumen textual y registrar fuente o autoría del video.
- Recuperar una producción previa sin convertirla en requisito para completar la clase.

## Recorrido estimado para 90 minutos

1. **Entrada, mapa visual y cuatro conceptos — 15 minutos.** Comparar cajas genéricas `div` con zonas que tienen significado. Recorrer en el esquema `header`, `nav`, `main`, `section` y `footer`, y mostrar la diferencia entre la URL para mirar un video y la URL `/embed/` para insertarlo.
2. **Mapa semántico y cuatro desafíos — 20 minutos.** Se diferencia entre hacer funcionar, hacer accesible, organizar y dar control. Los reintentos, pistas y soluciones forman parte del proceso y no descuentan puntos.
3. **Producción en el editor — 35 minutos.** El estudiante recupera M4, pega una copia externa o usa la plantilla autónoma. El editor ocupa todo el ancho y la vista previa queda debajo.
4. **Prueba con otra persona — 10 minutos.** Se comprueba comprensión sin reproducir el video, control del reproductor y ausencia de reproducción automática.
5. **Reflexión y PDF — 10 minutos.** El informe es exclusivo del módulo 5.

Los tiempos son una hipótesis de planificación, no evidencia de aplicación. Si la red escolar bloquea YouTube, se evalúan el código, la explicación y el resumen; no se penaliza una restricción de infraestructura.

## Notebooks compartidas

El módulo puede completarse sin datos locales anteriores. La plantilla contiene una estructura suficiente para realizar toda la actividad. Recuperar M4 es opcional y siempre produce una copia: no modifica la entrega anterior. Al finalizar se descargan `modulo5.html` y el PDF para Classroom.

## Evaluación formativa

La revisión automática detecta ocho condiciones observables, pero no califica la calidad del contenido ni demuestra accesibilidad completa. La revisión docente debe considerar:

- coherencia entre secciones y propósito;
- explicación de la elección técnica;
- utilidad del resumen o transcripción;
- fuente del video y uso responsable;
- cambios efectuados después de probar con otra persona;
- preguntas y dificultades registradas.

## Límites y cuidados

- Un `iframe` incorpora un servicio externo y puede fallar por red, configuración del video o políticas del proveedor.
- `youtube-nocookie.com` reduce almacenamiento previo a la reproducción, pero no vuelve privado al servicio ni elimina sus condiciones.
- El curso no descarga ni vuelve a publicar videos ajenos.
- La vista previa elimina scripts, formularios y direcciones de iframe no admitidas. Esto reduce riesgo, pero no reemplaza una revisión de seguridad completa.
- El PDF declara lo realizado; no prueba entrega, autoría ni disponibilidad futura del recurso externo.

## Evidencias a recoger en aula

- tiempo real requerido por conceptos, misiones y producción;
- confusión entre enlace para mirar y enlace para insertar;
- posibilidad de explicar `video` frente a `iframe`;
- uso real de la plantilla cuando cambia la notebook;
- bloqueos de red y decisiones adoptadas;
- calidad de los resúmenes sin reproducción;
- cambios posteriores a la prueba entre pares;
- preguntas que indiquen si el grupo está preparado para iniciar CSS.
