# Módulo 7 · CSS en su propio archivo

## Propósito

Separar HTML y CSS para presentar el producto en una one page sencilla. El grupo parte del CSS interno del módulo 6 y conserva las cuatro propiedades conocidas. No se agregan clases, modelo de caja ni Flexbox en este módulo.

## Apertura docente y autogestión (80-90 minutos)

- 0-15: recorrer el ejemplo antes/ahora. Mover una regla del bloque style al archivo estilos.css y conectar desde head. Mostrar qué sucede si los nombres no coinciden.
- 15-30: resolver la clasificación de fragmentos y los tres desafíos. Reintentos, pistas y soluciones quedan registrados sin penalización.
- 30-60: crear o recuperar una página con nombre del producto, descripción propia, imagen con alt y estilos legibles. No exigir video ni nuevas técnicas.
- 60-70: probar con un compañero, modificar una regla y registrar una mejora.
- 70-90: compartir la página en el espacio indicado por la docente, comprobar el enlace, responder la reflexión y guardar el PDF.

Los tiempos son una propuesta; si compartir el proyecto lleva más tiempo, completar el cierre en la clase siguiente.

## Preparación antes de la clase

La docente debe indicar un espacio de publicación o editor compartido que permita trabajar con HTML y una hoja CSS externa, y comprobar su acceso desde las notebooks. El curso no supone que YachayCodex u otra plataforma admita esa modalidad. Si solo permite un documento HTML con style interno, elegir otro espacio para esta actividad. El sitio no publica por sí mismo los trabajos.

El ZIP contiene index.html y estilos.css. Las imágenes locales deben conservarse y subirse aparte con su ruta correcta. La vista integrada muestra imágenes HTTPS; las imágenes locales se revisan en la carpeta del proyecto o en la publicación. No exigir datos personales ni contacto real de estudiantes en la página.

## Entrega y evaluación

Un PDF individual incluye el enlace clicable a la one page del equipo, observación, elecciones, historial de intentos de cada misión, pistas, soluciones consultadas, plan, prueba, mejora, reflexión y los dos códigos finales. Se requiere un enlace HTTP/HTTPS público en formato válido y la declaración de haberlo abierto; esto no prueba disponibilidad, acceso desde otra cuenta ni correspondencia con el código. La revisión docente verifica esas condiciones.

Se permite preparar un informe con pendientes académicos visibles para no inventar respuestas ni ocultar procesos incompletos. La docente evalúa comprensión del producto, claridad, separación de archivos y explicación de decisiones.
